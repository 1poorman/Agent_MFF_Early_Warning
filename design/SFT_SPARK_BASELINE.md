# 三、解读：持平不是巧合，是"缺规则"的必然

S1 用的是**退化版 prompt** —— 按 MS2 设计，它删掉了 `_build_prompt` 里的
**「判定规则」节**（`PQ≥+10% → 结垢`、`流量<6.4 且 PQ<+10% → 堵塞`、
`湿度>70%RH → 泄漏`、`压力std>3kPa 且 湿度≤65% → 气蚀`）。
退化版只留 stats 数值与工单，**而鉴别规则正是 SFT 要内化的东西**。

于是两个模型都只能靠"PQ 特性偏移高 ⇒ 阻力增大"这一条直觉去猜：

- 结垢 31 条 → 全判堵塞（缺"流量/湿度"的排除条件）
- 泄漏 56 条 → 全判堵塞（湿度铁证规则被删）
- 气蚀 44 条 → 42 条判堵塞（压力震荡规则被删）
- 工况切换 20 条 → 全判堵塞（"工况波动不报故障"的规则也被删）

**所以 S1 测的是"没规则时的下限"，两者都触底。它不能证明 Spark 与 2B 能力相同，
只能证明：在这个被刻意削弱的口径下，Spark 没有展现出任何 4B 相对 2B 的优势。**

# 四、四点对 S2（训练）不利的信号

1. **思考模式彻底不可用**（见第五节）—— 这是最硬的一条。
2. **时延 2.8×**：P50 3.01s / P95 3.54s（2B 为 1.08 / 1.42s）。
   ≤5s 前置契约仍满足，但余量从 3.6s 压到 1.5s；共享机 GPU 争用时 P95 有越界风险。
3. **系统性过度自信**：判错样本平均 conf **0.937**（2B 0.85），`≥0.8 比例 = 100%`。
   生产上这比"不准"更危险。SFT v3 的校准项本就已判"判据不适用"，Spark 起点更差，
   指望它解锁 MS7 校准目标的希望不大。
4. **输出分布更窄**：关思考下 24 条分层抽样只吐出 **2 个标签**
   （`过滤器堵塞`×20、`管道泄漏`×4）；2B 至少吐 3 个。塌缩更严重。

# 五、思考模式：**彻底不可用**（`tools/spark_thinking_probe.py` 实测）

| 模式 | 准确率 | 时延 | 现象 |
|---|---|---|---|
| 关思考（n=24） | 1/24 = 4.2% | 均值 3.1s，最大 3.8s | 只输出 2 个标签；transition/antihall 全错 |
| 开思考（n=24，上限 1200 tok） | **0/24** | 全部 16.0s | 1200 token 顶满，**JSON 解析不出** |
| 开思考（上限 6000 tok） | **0 有效** | **80.3s / 76.8s** | 6000 token 顶满、5717 token 仍未结束，**仍无有效 JSON** |

- 非思考下 **2.9~3.4s** 产出 200~280 token 的完整 JSON；
- 思考下 **76~80s** 写了 5700~6000 token **还没写完思考链**，更没到 JSON。

即使把 `--max-model-len` 从 8192 提到 16k/32k 让思考跑完，单条也将是
**100s 量级** —— 是「2B 前置 ≤5s」契约的 **20 倍以上**，也远超 27B 兜底的 ≤10s。

> **结论：Spark-X2.5-4B 在本任务上只能走非思考模式，而思考恰是它被设计的强项；
> 非思考模式下它塌缩到 2 个标签 —— 这条线在本任务上"两头不靠"。**

# 六、决策门判定（对照 `docs/SFT_SPARK_X25_4B_PLAN.md` §1.2）

| 门槛 | 判定 |
|---|---|
| 故障子集 ≥60% 且混淆对 ≥50% → 通过 | ❌ 20.6% / 30.0% |
| 故障子集 40~60% → 降级 | ❌ |
| **故障子集 <40% → 终止** | ⬅ **命中** |

⚠️ **但须指出该门槛的设计缺陷**：写门槛时照搬了 MS1 的"≥60% 通过"，
而 MS1 的 64.0% 是在**完整 prompt（含判定规则）**下测的，与 S1 的退化 prompt 不同口径。
S1 真正可比的锚点是 **2B 在退化 prompt 下的 20.6%**。
按此重读：**Spark 与 2B 原生完全持平 —— 这道门对本阶段没有判别力。**

**S1 的诚实结论：原生没有更好的效果（与 2B 持平），而非"Spark 不行"。**
但第五节的证据独立于该门槛且更强：**思考模式不可用 + 非思考塌缩更严重 +
时延 2.8× + 校准起点更差** —— 四条合起来，使"训练后能否超过 2B"的预期收益明显偏低。

# 七、完整生产 prompt 口径对照（MS1 口径，86 窗口）

退化版 prompt 只测出"没规则时的下限"。生产级联前置实际拿到的是**完整**
`_build_prompt`（含 L1 告警、判定规则、图谱候选）。故补做 MS1 口径对照：

```bash
conda run -n mff_agent python tools/ms1_baseline.py \
  --url http://localhost:3762/v1 --model Spark-X2.5-4B --cascade off \
  --out data/sft/ms1_baseline_spark.jsonl
```

> ⚠️ **`--cascade off` 是本轮新增的必要开关**：`ms1_baseline.py` 走
> `svc.diagnose()` 完整流水线，而 `.env` 里 `cascade_enabled: true`，
> 于是 27B 兜底会救回大量样本 —— 测出来的就不是该模型自己的能力了。
> **2026-09-09 的 2B MS1 基线跑在级联引入（MS6，09-11）之前，是纯单模型口径**，
> 因此任何后续同口径对照都必须传 `--cascade off`。首次未加该开关的 Spark 运行
> 已作废（日志中可见大量 `172.25.67.140` 27B 调用）。

| 指标（关仲裁，n=86 窗口） | MiniCPM5-2B（09-09） | **Spark-X2.5-4B（09-14）** | 差异 |
|---|---|---|---|
| **根因准确率** | **64.0% ± 0.9%**（3 次复跑） | **61.6%** | **−2.4pp（略差）** |
| 含仲裁准确率 | 81.4% | 81.4% | 持平 |
| JSON 合法率 | 100% | 100% | 持平 |
| LLM 平均时延 | **1.23s** | **3.38s** | **Spark 慢 2.7×** |
| 水泵气蚀 | 0.0% (n=12) | 0.0% (n=12) | 持平（都全错） |
| 管道泄漏 | 8.3% (n=12) | **0.0%** (n=12) | Spark 差 1 条 |
| 线圈结垢 | 87.5% (n=56) | 83.9% (n=56) | Spark 差 2 条 |
| 过滤器堵塞 | 100.0% (n=6) | 100.0% (n=6) | 持平 |
| 复合故障（观察项，n=10） | — | 10/10 输出 `过滤器堵塞` | 未与金标签比对 |

**结论：在完整生产 prompt 下，Spark 与 2B 同为"结垢能判、气蚀/泄漏判不出、
其余全塌缩到过滤器堵塞"的同一失效模式，且 Spark 略差 2.4pp、慢 2.7×。**

> 两轮运行窗口数完全一致（总 136 行 / 故障 86 / 正常 40 / 复合 10），
> 说明 `sample_windows` 采样未变，对照成立。
> 对照脚本：`tools/ms1_summarize.py <2B.jsonl> <spark.jsonl>`
