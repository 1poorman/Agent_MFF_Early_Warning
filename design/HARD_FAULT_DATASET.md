# 八类故障仿真与独立难例数据集

完成日期：2026-09-29。数据版本：`hard_faults_v1`。

仿真器从四类扩展为八类可注入故障，已生成 **1,380 条样本 / 690 个仿真炉次**，
包含复合故障、轻微劣化、关键传感器缺失、误导工单和评估工况偏移。
本轮按“扩展仿真和数据集”的范围完成，尚未在八类数据上重训或评估模型。
这些设计增加了诊断挑战，实际难度变化仍需后续模型评测确认。

## 新增故障机制

原有过滤器堵塞、水泵气蚀、管道泄漏、线圈结垢继续保留。
新增机制通过物理状态更新影响观测，输出仍使用原有传感器列和单位。

| 新增故障 | 注入机制 | 主要信号 | 需要排除的混淆 |
|---|---|---|---|
| 换热器散热衰退 `heat_exchanger_degradation` | 冷端附加热阻最大 0.06 K/kW，180 s 一阶热惯性 | 进水与出水温度共同上升，水侧热平衡继续联立计算 | 高环境温度、结垢导致的温升 |
| 水质恶化 `water_quality` | 电导率附加增长项最大 0.6 µS/cm/s | 电导率升高 | 初始水质差异、补水稀释、泄漏后自动补水 |
| 电气柜散热风机失效 `cabinet_fan_failure` | 柜体热阻随故障进程增加，温升系数最高为原值的三倍 | 相同功率和环境温度下柜温偏高 | 高负载、环境升温 |
| 补水阀卡开 `makeup_valve_stuck_open` | 最大 1.5 L/s 非指令补水，参与液位质量平衡及水质稀释；超过 3 m 溢流 | 液位上升、电导率下降 | 正常补水、泄漏与补水并发 |

以上最大效应对应故障进程为 1；样本使用不同严重程度和渐变时长。
这是简化机理仿真：柜温采用热阻代数模型，电导率污染采用等效源项，
不代表已用实际设备的风机曲线、污染物输运或换热器参数完成校准。

这些属性可以重叠，不能逐项相加。`meta.kind` 是一个摘要分类：

复合故障选择八组：堵塞＋换热衰退、泄漏＋水质恶化、结垢＋风机失效、
气蚀＋补水阀卡开、水质恶化＋补水阀卡开、堵塞＋泄漏、结垢＋换热衰退、
风机失效＋水质恶化。既包含跨系统并发，也包含共享通道或相互抵消的机制。
这些配对在三个集合均出现；本版本没有将未见过的故障组合单独留作测试。

单故障严重程度为 0.08、0.2、0.5、0.85，复合故障为 0.5、0.85；
渐变时长为 180、600、900 s。每个炉次长 1,800 s，从第 300 s 开始注入故障。
两个当前窗口分别为 `[600,1200)`、`[1200,1800)`，参考观测来自 `[120,300)`。
均值取各窗口末尾 120 s，去趋势标准差和每分钟变化率取完整窗口。
每个炉次的两个窗口保持在同一集合中，后续统计置信区间应按炉次重采样。

## 可观测性与输出格式

输入只包含候选故障域、设备标定、参考观测、当前统计、工况、缺失通道和维修工单。
种子、注入时间/严重程度和反事实数据仅保存在 `meta`，不会进入模型提示词。
训练时仅使用 `messages`，不能将整条 JSON 连同 `meta` 拼进输入。

对每个注入根因，使用相同配置和种子回放“只移除该根因”的配对仿真，
计算可见通道相对变化。任一相关通道超过门槛才保留该根因的标签。
门槛为温度 0.3 ℃、流量 0.12 L/s、压力 1.5 kPa、液位 1.5 cm、
电导率 8 µS/cm、柜温 0.6 ℃、湿度 1.5 %RH；气蚀另检查压力去趋势标准差变化 0.25 kPa。
缺失通道不参与支持度计算。门槛是仿真教学规则，并非统计显著性或实测检测限。

反事实差异验证的是该原因在当前模拟中能否影响可见观测，
**不能证明仅凭提示词就能唯一识别根因**。特别是共享通道和抵消效应，
仍可能存在难以区分的候选解释。后续应增加盲审或可辨识性分析来检验标签质量。

输出采用多根因集合：

```json
{
  "root_cause": "水质恶化 + 电气柜散热风机失效",
  "root_causes": ["水质恶化", "电气柜散热风机失效"],
  "needs_more_data": false,
  "confidence": 0.7,
  "evidence": ["从可见观测引用的均值、去趋势标准差及变化率"],
  "sop": ["各可辨识根因对应的处置建议"]
}
```

`root_causes` 不设主次，`root_cause` 按名称排序后连接；完全无可辨识原因时，
填“无故障（工况变化或正常波动）”或“证据不足（建议补充测量）”。
复合故障部分可辨识时保留已有证据支持的原因，同时 `needs_more_data=true`。
例如评估样本 `eval-00119` 的第 1,200 s 窗口隐藏了流量、压力与出水温度，
只保留“管道泄漏”，并请求补充观测以确认其他原因。

`confidence` 为合成教学值 0.45 / 0.7 / 0.85，**不是校准后的正确概率**。
不应将拟合这几个置信度值解读为模型概率校准改善。

## 隔离与验证

训练、验证、评估分别从种子 11000、21000、31000 起生成，设备 ID 与种子绑定；
集合之间的输入、种子、仿真炉次和设备 ID 均无重叠。
设备参数在同一仿真模型中随机采样，设备 ID 隔离不等于真实独立设备验证。

训练/验证环境温度为 24–31 ℃、进水基线 25–30 ℃、额定功率 2500–3200 kW。
评估按炉次随机选择约一半使用 31–38 ℃、31–35 ℃、1800–2500 kW 的偏移范围，
最终得到 148/268 条偏移样本；所有故障类别采用相同采样规则。

已完成的检查：

- 全量 1,380 条输入唯一、统计数值有限、证据完整文本与观测逐项对应、集合标签与可观测性规则一致。
- 三个集合及五份旧 SFT/RL 数据之间没有输入或种子交叉；旧数据 SHA256 全部与既存 RL 清单一致。
- 数据文件、五份生成源码快照及当前源码的 SHA256 一致。
- 每个集合回放八种单故障、八种复合故障、正常工况各一个炉次，共 51 个炉次 / 102 个窗口；参考与当前统计全部一致。
- 四项单元测试通过，覆盖旧正常/四故障 CSV 指纹、新故障信号及水侧热平衡、补水质量平衡与溢流、缺失通道标签及集合隔离。

机器可读核验结果：[audit_final.json](../logs/hard_sft_20260928/audit_final.json)。
运行环境：Python 3.10.20、NumPy 2.2.6、pandas 2.3.3。
旧四类数据、生产知识图谱及已有模型权重保持原版本；新增类尚未接入生产推理评估链路。

## 后续模型对照口径

旧 [SFT / DPO / GRPO 对照](SFT_RL_COMPARISON.md) 的结论适用于旧四类测试，
不能直接作为八类故障性能。旧单根因奖励和评估器尚不完整支持这里的多根因格式。
后续应先适配集合完全匹配率、八类 macro-F1、`needs_more_data` 精确率/召回率、
正常误报、证据忠实和格式合法性，并分别报告复合、缺失、弱信号及偏移工况结果。
偏好构造与奖励设计只使用训练集；验证集用于选型，评估集冻结后用于最终比较。
本轮没有启动这些新训练或将规则生成标签称为人工 RLHF / AI 裁判 RLAIF。
