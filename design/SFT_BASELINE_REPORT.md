# SFT 基线试验报告（MS1）

> 日期：2026-09-09 · 对应里程碑：[SFT_MILESTONES.md](../docs/SFT_MILESTONES.md) MS1 · 状态：✅ 已通过决策门
> 脚本：`tools/ms1_baseline.py` · 明细：`data/sft/ms1_baseline_results.jsonl`（3 次复跑）

## 一、试验目的与结论

**问题**：MiniCPM5-2B 原模型（未训练）在本项目根因诊断任务上的上限是多少？

**结论**：关仲裁根因准确率 **64.0% ± 0.9%**（3 次复跑），**≥60% 决策门 → 投入全参 SFT（MS2 启动）**。

| 决策门 | 阈值 | 实测 | 判定 |
|---|---|---|---|
| 投入 SFT | ≥60% | **64.0%** | ✅ **通过** |
| 降级为级联初筛 | 40~60% | — | — |
| 终止 2B 路线 | <40% | — | — |

## 二、评估方法

- **组包口径**：镜像实时流路径 `service._diagnose_async`（demo 主链路）——stats 窗口统计 +
  工况上下文（diag_context）+ 图谱候选 + 统计预鉴别，**不注入 L1/L2**（与线上一致；
  批量路径 `analyze()` 全量注入 L1 会导致持续越限故障 prompt 爆炸，非线上真实分布）。
- **提示词**：`_build_prompt` 原样（**含完整判定规则**——即模型在规则全部给足的情况下测，
  结果仍然 64%，印证提示工程已达上限）。
- **端点**：本地 vLLM（MiniCPM5-2B，GPU0，`enable_thinking=false`，max-model-len 32768，temp 0.1）。
- **评估集**：86 个单一故障窗口（滑窗 1200s / 步长 600s，尾段 120s 金标签）：
  气蚀 12、泄漏 12、结垢 56（标准+重度）、堵塞 6；另 10 个复合故障窗口（观察项）、
  40 个正常窗口（上游误触发，不调 LLM）。
- **指标口径**：关仲裁 = LLM 首次输出解析的 `root_cause` 对金标签命中率（不含
  `root_cause.py` 图谱/统计仲裁——那是 SFT 要内化的对象）。

## 三、结果（3 次复跑均值 ± 波动）

| 指标 | 结果 | 说明 |
|---|---|---|
| **关仲裁根因准确率** | **64.0% ± 0.9%** | 决策门指标，三次 65.1/62.8/64.0 |
| 含仲裁准确率（参考） | 81.4%（三次全同） | 仲裁+统计预鉴别确定性修正 |
| JSON 合法率 | 100% | 格式能力无需训练 |
| 防幻觉重试率 | 0/86 | 物理校验全过 |
| LLM 平均时延 | 1.2s | 远低于 5s 契约，2B 速度红利显著 |
| 正常窗口上游误触发率 | 2.5% (n=40) | L1/L2 层，与模型无关 |

### 分故障类别（关仲裁）与混淆矩阵

| 金标签 | 准确率 | 模型实际输出分布 |
|---|---|---|
| 线圈结垢 | 86.9% | 结垢 49 / 堵塞 7 |
| 过滤器堵塞 | 100% | 堵塞 6/6 |
| **水泵气蚀** | **0.0%** | **堵塞 12/12** |
| **管道泄漏** | **2.8%** | **堵塞 11 / 泄漏 1** |

复合故障（观察项）：10/10 全部输出"过滤器堵塞"（单一主根因，schema 不支持复合输出，符合预期）。

## 四、关键发现

1. **失败模式高度系统化，非随机噪声**：模型存在强烈的"默认判过滤器堵塞"偏置——
   气蚀/泄漏窗口几乎全军覆没于该偏置。这正是 SFT 配平数据（混淆对 ≥600 条）能修复的类型，
   且是当前代码仲裁（`root_cause.py:202-219` 专门纠正气蚀↔泄漏↔堵塞）在兜底的同一组场景——
   与 SFT 方案的靶点完全吻合。
2. **格式与速度零差距**：JSON 100%、1.2s/次、防幻觉校验全过。2B 的差距**纯粹在领域鉴别**，
   不在指令跟随——理想的 SFT 起点（训练目标单一）。
3. **提示工程确已到顶**：判定规则全文注入（含"压力std>3kPa 且湿度≤65%RH → 气蚀"的显式规则），
   模型仍不能应用数值规则——印证蓝图 ADR（知识必须入权重）。
4. **含仲裁 81.4% < 线上 27B 的 100%**：2B+现有仲裁尚不达线上水准，级联部署（27B 兜底）
   保持为必要设计；SFT 目标：关仲裁 ≥90%、含仲裁对齐 100%。

## 五、SFT 训练目标校准（据本基线）

| MS5 指标 | 基线 | SFT 目标 | 依据 |
|---|---|---|---|
| 关仲裁准确率 | 64.0% | ≥90% | 混淆对是唯一短板，配平数据主攻 |
| 气蚀/泄漏关仲裁 | 0%/2.8% | ≥85% | 数据配比重点（气蚀泄漏各 ≥400 + 混淆对 600） |
| JSON 合法率 | 100% | 保持 ≥99% | 防遗忘监控项 |
| 时延 | 1.2s | ≤5s | 已达标，SFT 后回归验证 |

## 六、局限与备注

- 堵塞样本仅 6 窗（`fault_demo_6h` 中 filter_clog 单故障段有限），其 100% 准确率置信度低；
  MS2 数据构造时用仿真器直接生成堵塞场景补足（`DataSimulator` 支持 `filter_clog` 注入）。
- 本评估为提示词含完整判定规则的条件基线；MS4 训练数据的输入是**去掉判定规则的退化版提示**，
  SFT 后的评估将与本基线同卷对比（含规则版）+ 退化版双口径，用于验证"知识已内化"。
- 单次评估约 86 次 LLM 调用（~2min），波动 ±0.9% 主要来自 temp 0.1 采样与 vLLM 批处理非确定性。

## 七、决策记录

> **MS1 决策门结论：通过（64.0% ≥ 60%），启动 MS2 SFT 数据构造。**
> 级联部署（6.6）维持为落地形态；MS7（RL）前置条件不变。
